# 微信小程序发布与上线运行手册

更新时间：2026-08-11

本手册是 MuseAI 小程序体验版上传、正式提交审核、发布后观察和前端回退的权威流程。运行功能说明留在 `README.md`；后端代码、数据库、真实数据和图片的部署与回退必须使用后端仓库 `docs/miniapp-content-maintenance.md`，不要从本文拼接服务器命令。

## 1. 当前发布基线

- 发布分支：`main`，上传前必须与 `origin/main` 指向同一提交。
- 2026-08-11 已验收前端基线：`fa209f8fe630df5194246ca769fc7aedc0b65d60`。
- 已通过：16 组前端自动化检查、微信发布预检、关闭合法域名豁免后的真机导览闭环，以及报告保存、建议上下文、停止生成恢复和键盘遮挡四项专项回归。
- 当前正式 API：`https://api.banpo-museai.xyz/api/v1`。
- 尚未完成：体验版上传和成员分发、馆方真实展品/图片/地图接入、OCR 上线决策、正式发布所需的隐私与平台材料。

后续每次上传都应在发布记录中写入实际 Git SHA，不能把本节的历史 SHA 当作永久目标。

## 2. 先判断本次发布类型

| 变更类型 | 正确顺序 |
| --- | --- |
| 仅小程序界面或客户端状态逻辑，后端契约不变 | 完成前端验证后直接上传；不重启后端 |
| 兼容性后端修复 | 先按后端手册部署并验证旧客户端仍可用，再上传小程序 |
| 新增或改变 API 字段 | 后端先提供向后兼容字段并验证，再发布消费该字段的小程序 |
| 仅真实展品、展厅文案或图片更新 | 使用后端数据/图片维护流程；前端代码通常不变，但要重新抽样真机 |
| 破坏性契约或数据迁移 | 不与微信审核同时执行；拆成可回退的兼容发布批次 |

微信审核期间除紧急故障外应冻结会影响审核路径的接口、数据结构和关键文案，避免审核包与线上状态不一致。

## 3. 上传体验版前

### 3.1 固定源码和上传边界

在 PowerShell 中执行：

```powershell
git fetch origin main
git status --short --branch
$local = git rev-parse HEAD
$remote = git rev-parse origin/main
if ($local -ne $remote) { throw "HEAD 与 origin/main 不一致" }

npm ci
npm run test:all
git diff --check
git status --short
```

门禁要求：

- 当前分支是 `main`，工作区无未提交内容，`HEAD == origin/main`。
- `test:all` 全部通过；其中 `test:preflight` 必须确认正式 HTTPS API、上传目录白名单和 `uploadWithSourceMap=false`。
- 本机 `project.config.json`、`project.private.config.json`、AppID、私钥、凭据和调试文件不得提交。
- 不临时放宽 `packOptions.ignore`，也不把 README、测试、Git/npm 文件或 source map 加入上传包。

### 3.2 开发者工具和真机冒烟

1. 用微信开发者工具打开本仓库根目录。
2. 清除缓存并重新编译，确认控制台没有脚本异常、资源 404 或未处理 Promise。
3. 关闭“不校验合法域名、web-view、TLS 版本以及 HTTPS 证书”。
4. 至少复核以下路径：
   - 无历史时首页不显示“继续上次游览”；默认导览和问卷导览都能进入展厅。
   - 展厅目录、路线、展品列表、展品详情和缺图回退正确。
   - 展品讨论后离厅重入不残留展品建议；等待首段和流式输出中停止后建议恢复。
   - 长回答、键盘抬升和停止输出后最后气泡不被输入栏遮挡。
   - SSE、复制、TTS、报告生成和“保存本次记录”正常。
5. 若本轮改变了布局、键盘、媒体或权限，至少各用一台 iOS 和 Android 设备复核；纯文档发布不需要重新上传小程序。

## 4. 上传和分发体验版

优先使用微信开发者工具的“上传”入口，避免把上传私钥或 AppID 写入仓库脚本。

1. 记录本次版本号、Git SHA 和简短版本说明；版本说明只写用户可验证的变化。
2. 在开发者工具确认 AppID、上传包体积和正式 API 后执行“上传”。
3. 到微信公众平台的版本管理中确认该开发版本，设置为体验版。
4. 配置体验成员并分发体验二维码；不要把体验二维码当作正式发布链接。
5. 由非开发者成员至少完成一次默认导览、一次问卷导览、一次展品讨论和一次报告保存。
6. 在发布记录中写明设备系统、基础库版本、结果和未通过项。

开发者工具或公众平台的具体按钮名称可能随版本调整，但必须保持“固定 SHA → 本地门禁 → 上传开发版本 → 设置体验版 → 成员真机验收”的顺序。

## 5. 正式上线前门禁

以下项目全部有明确结论后才提交审核：

- 产品与数据：九厅名称/简介确认；真实展品和授权图片已导入并抽样；测试数据不会被误当馆方内容；地图/路线未接入时不展示虚假能力。
- OCR：二选一——购买配置并真机验收，或隐藏拍照识别入口并保留文字搜索；不能以未配置入口提交审核。
- 微信配置：正式 AppID、开发者/上传/审核权限、服务器域名、业务域名和实际使用到的接口域名均已确认。
- 隐私与内容：隐私政策、用户协议、相机/相册/语音相关说明、AI 生成内容说明与小程序实际行为一致。
- 后端：公网 `/api/v1/ready` 正常；生产发布、数据库/图片备份和恢复证据完整；唯一管理员和持久图片目录已核对。
- 服务资产：第三方模型和语音服务的负责人、额度、付费、限流、告警与轮换记录在私有运维文档中；仓库不记录取值。
- 验收：体验版使用最终候选 SHA，iOS/Android 完整闭环通过，严重级别故障为零。

## 6. 提交审核和发布当天

1. 冻结候选前端 SHA、后端 SHA、真实数据来源版本和图片批次。
2. 用最终候选重新执行第 3 节门禁，上传同一源码生成的版本。
3. 在公众平台填写版本说明、服务类目、隐私与权限材料并提交审核。
4. 审核期间保持生产 API 向后兼容，不做无关数据清洗、模型切换或基础设施迁移。
5. 审核通过后选择发布；记录正式版本号、发布时间、前后端 SHA、数据来源版本和操作人。
6. 发布后立即执行第 7 节验证，不以“平台显示发布成功”代替业务验收。

## 7. 上线后处理

### 发布后 30 分钟内

- 从正式入口冷启动小程序，完成 session 创建、展厅目录、一次 SSE 回答、TTS、展品详情和报告。
- 核对后端公网 readiness、systemd 状态、重启次数和发布后错误日志。
- 抽查九厅名称/短简介、真实展品数量、图片读取和测试标记是否符合发布批次。
- 检查模型/TTS 服务是否出现额度、限流或认证失败。

### 首个 24 小时

- 关注会话创建、SSE 中断、TTS、报告、图片和 5xx 错误；只记录聚合结果，不收集不必要的游客原文。
- 核对 CPU、内存、磁盘、数据库/Redis/Elasticsearch readiness 和 systemd 重启次数。
- 确认当天数据库备份成功并可校验；有真实上传图片时确认图片备份属于同一发布批次。
- 对真实游客反馈先复现和归类；单次审美意见不立即触发 UI 改版，重复的阻断问题优先修复。

### 稳定运行后

- 每日：readiness、关键错误、第三方服务额度和最近备份。
- 每周：抽样完整导览、备份恢复能力、磁盘增长、证书到期时间和真实数据抽样。
- 每次数据更新：重新检查展厅筛选、建议条、图片、展品讨论和报告摘要。
- 每次代码发布：重新走本手册，不以“只改一点”为由跳过 SHA、预检和发布记录。

## 8. 前端故障回退

| 故障范围 | 处理方式 |
| --- | --- |
| 体验版问题 | 停止分发该体验版，修复后用新版本号重新上传 |
| 正式小程序客户端问题 | 使用公众平台可用的版本回退/重新发布能力，或从已验证旧 SHA 构建紧急修复版；随后完整冒烟 |
| 后端接口或迁移问题 | 不改客户端缓存掩盖；按后端 `docs/miniapp-content-maintenance.md` 第 9 节回退 |
| 数据或图片错误 | 停止继续导入，保留现场，按后端同批次数据库/图片记录回退 |
| 第三方模型/TTS 故障 | 保持客户端契约不变，按私有运维预案降级或更换配置，并重启验证 |

触发回退时先记录版本、SHA、开始时间、错误表现和影响范围。不要清空用户本地缓存作为通用修复；只有确认缓存格式本身损坏时才采用定向迁移或清理。
